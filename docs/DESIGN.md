# 设计说明

## 决策

本项目以**提示词驱动的原生桌面补丁**作为唯一发布方式，不提供 Cordis 插件、托盘助手或常驻脚本。

目标责任只有一个：把“重启 DeepSeek Harness”放进 DSH 已有的官方 Electron 托盘菜单，并让它调用主进程已有的重启与退出能力。

## 背景

DSH 桌面端至少包含两类进程：

```text
Electron 主进程
├─ 拥有 app、Tray、Menu
└─ 创建官方 DesktopTray

Cordis 宿主子进程
├─ 以纯 Node 模式运行
└─ 无 Electron Tray/Menu 扩展点
```

Cordis 插件不能直接向官方托盘加菜单项。若插件自己启动 WinForms、Electron 或其他托盘助手，就会形成第二个图标、第二套生命周期和额外故障面。

因此，本项目选择官方 Electron 主进程作为唯一行为所有者。

## 不变量

任何版本的提示词都必须保持：

1. **单图标**：只使用官方 DSH 托盘。
2. **单一重启实现**：菜单调用 `this.options.restart()`；托盘 options 中只有一个对应回调。
3. **原生顺序**：`app.relaunch()` 先登记重新拉起，再调用 `quitWithoutConfirmation()`。
4. **最小差异**：源代码差异只允许落在官方托盘菜单项与同一托盘实例 restart options 两个语义区域，并且只修改实际缺失/错误的区域；保留所有无关本机改动。
5. **幂等**：中英文两套完整标签、位置、菜单调用与回调都已正确时，第二次运行零文件写入、零备份、零重建、零临时产物。
6. **能力分支**：所有分支先通过只读逐条 integrity 与 Electron 运行时策略门；只有修改分支再执行零改动 ASAR round-trip/writer 能力门。
7. **备份先行**：原始与全新不覆盖的备份 SHA-256 一致后才允许编辑。
8. **staged 验证**：正式归档仅在允许区域源码 diff、语义清单、逐条 integrity、运行时策略和重读检查全部通过后才替换。
9. **拒绝猜测**：锚点不唯一、ASAR 无法可靠重建、运行时策略不明或正式文件中途变化时停止。
10. **零运行时扩展**：无插件、常驻助手、服务、计划任务、注册表、启动项和补丁专用网络依赖。

## 补丁契约的所有权

规范性的安装契约只存在于 [README 的完整提示词](../README.md#可直接复制的完整提示词) 中，本设计文档不复制第二份实现配方。

设计层只约束以下不变量：菜单必须属于官方托盘、标签必须包含完整产品名、菜单调用与同一托盘实例的唯一 restart 回调相互对应、重启登记先于退出。具体本地化组合、结构锚点、状态分支和验证步骤以权威提示词为准；若两份文档出现冲突，停止并修正 README，而不是在此维持兼容分支。

## 为什么不固定行号

`app.asar` 中的 `lib/main.js` 是构建产物。版本升级、打包器变化或用户已有改动都会改变行号与格式。提示词使用两处相互关联的结构锚点：

- 官方托盘菜单构造处；
- 创建同一托盘实例并传入 `open`/`quit` options 的位置。

两处都唯一时才允许修改。全局发现 `app.relaunch()` 并不能证明它属于托盘。

## ASAR 更新模型

原始归档不是源码仓库。安全流程为：

```text
只读探测 + 逐条 integrity + Electron embedded-ASAR/fuse/签名策略门
  → 同时求值中英文完整标签并判定状态
  ├─ 已安装：零文件写入、零临时产物，直接报告
  └─ 需修改：零改动 ASAR round-trip/writer 能力门
       → 全新原件备份 + SHA-256
       → staged 归档
       → JS 语法 + 允许区域逐行源码 diff
       → 全归档内容/语义元数据 + integrity 比较
       → 两种语言的完整标签/位置/调用/回调幂等性检查
       → 正式文件与备份哈希紧邻复核
       → 同卷安全替换
       → 重读正式归档
```

`app.asar.unpacked` 不属于本功能的修改面。除 `lib/main.js` 内容以及由其尺寸引起的 offset/integrity 更新外，归档中任何内容或语义元数据差异都会阻止应用。结构可读不等于 Electron 一定接受；运行时策略无法证明时同样停止。

## 更新与回滚

DSH 更新器可能整体替换 `app.asar`。因此：

- 更新后菜单消失是可预期状态，重新运行提示词即可；
- 备份与 DSH 构建绑定；
- 当前归档哈希只有在等于 manifest 的 patched hash 时，才允许直接恢复 original backup；
- 哈希不同意味着存在更新或其他改动，应停止直接覆盖。

详见 [ROLLBACK.md](ROLLBACK.md)。

## 非目标

- 不为 `dsh web` 提供托盘。
- 不建立通用 Electron 补丁框架。
- 不绕过 DSH 更新或签名机制。
- 不替用户自动点击重启。
- 不删除未确认的旧插件或第三方文件。

## 风险表

| 风险                   | 控制                                                         |
| ---------------------- | ------------------------------------------------------------ |
| 版本结构变化           | 唯一结构锚点；不唯一即停止                                   |
| 标签只有“重启/Restart” | 对中英文完整产品名做状态与幂等验证                           |
| 重复安装               | 同时检查中英文完整标签/位置/调用/回调；已安装分支零文件写入且无临时产物 |
| ASAR 损坏              | 修改分支的零改动 round-trip、staged 全量重读、逐条 integrity 与语义比较 |
| Electron 拒绝修改归档  | embedded-ASAR/fuse/签名策略门；无法证明即停止                |
| 覆盖其他本机补丁       | 逐行 diff 只允许两个语义区域，只改实际缺失/错误处；不用旧备份生成新文件 |
| 错把旧版备份盖到新版   | manifest 哈希门控 + 离线替换紧邻前再次检查                   |
| DSH 退出后 Agent 消失  | Agent 只生成计划；用户在外部 PowerShell 手动执行一次性恢复块 |
| 第二托盘残留           | 运行时负向检查；旧插件只在确认后清理                         |
| 自毁式验证中断任务     | 不自动重启，交由用户选择测试时机                             |
