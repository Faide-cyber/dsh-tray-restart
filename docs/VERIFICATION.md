# 验证清单

本清单验证两个方向：新功能确实由官方托盘承载；旧的插件/助手路径确实没有继续运行。

## 1. 应用前证据

Harness 的最终报告应包含：

- [ ] DSH 版本与唯一安装路径
- [ ] 正式 `resources/app.asar` 路径
- [ ] 官方托盘菜单结构锚点
- [ ] 同一托盘实例的 options 结构锚点
- [ ] 当前归档所有条目的 integrity hash/blocks 可从实际 payload 只读复验
- [ ] Electron embedded-ASAR integrity/fuse/签名策略已只读检查；若进入修改分支，它允许修改后的归档，否则已停止
- [ ] 状态判定分别求值并同时覆盖完整中英文标签、菜单位置、唯一调用与唯一回调

仅修改分支还必须包含：

- [ ] 本机 ASAR 读写方式及零内容改动 round-trip 结果
- [ ] 原始归档 SHA-256
- [ ] 全新且不覆盖旧目录的备份路径与备份 SHA-256
- [ ] 原始哈希与备份哈希一致
- [ ] `manifest.json` 已写入基线字段

“原本已安装”分支应明确记录零文件写入、零临时产物，并跳过 ASAR round-trip、备份、重建和替换。缺少任意适用项，不应应用补丁。

## 2. 静态验证

- [ ] 修改后的 `lib/main.js` 通过 JavaScript 语法检查
- [ ] 逐行源码 diff 的每条变化都属于官方托盘菜单项或同一托盘实例 restart options 两个允许区域之一；只修改实际缺失/错误的区域，不用 unified-diff hunk 数量判断，且无全文件格式化/编码/换行变化
- [ ] 官方托盘菜单上下文中只有一次 `this.options.restart()`
- [ ] 对应托盘实例中只有一个 `restart` 回调
- [ ] 回调按顺序调用 `app.relaunch()` 与 `quitWithoutConfirmation()`
- [ ] 重启项位于分隔线后、退出项前
- [ ] 中文/英文可见标签完整等于“重启 DeepSeek Harness”/“Restart DeepSeek Harness”；不能接受单独的“重启”/“Restart”
- [ ] staged ASAR 可完整读取
- [ ] 除 `lib/main.js` 内容及必需的物理 offset 变化外，所有归档路径、类型、内容、unpacked/可执行标记、链接目标与语义元数据相同
- [ ] 每个 staged 条目的实际 payload 均匹配其 integrity algorithm/hash/blockSize/blocks，目标条目的 integrity 已按新字节更新
- [ ] `app.asar.unpacked` 未修改
- [ ] 运行时 embedded-ASAR integrity/fuse/签名策略不会拒绝 staged 产物
- [ ] 同一完整检测流程第二次运行分别验证中英文完整标签并判定“已安装”，产生零文件写入、零临时产物、零重建
- [ ] 应用紧邻前再次确认正式归档与备份哈希均未变化
- [ ] 应用后重读正式归档，结果与 staged 一致

## 3. 托盘实测

先等待所有 Agent 任务结束，再完全退出并重新打开 DSH。

- [ ] 系统通知区域中只有一个 DSH 托盘图标
- [ ] 右键该图标可见“重启 DeepSeek Harness”或“Restart DeepSeek Harness”
- [ ] 原有“打开”和“退出”等项目仍存在
- [ ] 点击“打开”仍能聚焦/打开 DSH
- [ ] 保存工作后点击“重启”，当前桌面端退出
- [ ] DSH 自动重新拉起，无需手动启动 exe
- [ ] 原会话仍可从 DSH 的正常持久化机制中打开

重启会结束当前进程，测试结果应从**重新拉起后的新进程**观察，而不是从旧进程等待返回。

## 4. 负向检查

本功能不应产生以下任何对象：

- [ ] profile 中没有新增 `dsh-tray-restart` Cordis insert/bundle
- [ ] profile `node_modules` 中没有为本功能创建的链接或包
- [ ] 没有命令行包含 `tray.ps1` / `dsh-tray-restart` 的常驻 PowerShell
- [ ] 临时目录没有本功能使用的 alive flag 或运行日志
- [ ] 没有新增服务、计划任务、注册表项或开机启动项
- [ ] 没有第二个 DSH 托盘图标
- [ ] 没有补丁专用网络下载/请求或凭据访问；正常 Harness 模型通信不计入补丁行为

如果用户原本已安装同名旧插件，应先报告精确路径并获得确认，再做删除；不要把其他插件误判为残留。

## 5. 更新后复查

DSH 更新后：

1. 先检查版本和当前 `app.asar` 哈希。
2. 菜单仍存在：只验证，不重复写入。
3. 菜单消失：在新版本上重新运行 README 提示词。
4. 当前哈希与旧 manifest 不同：不得直接恢复旧备份。

## 6. 失败分类

| 失败 | 处理 |
| --- | --- |
| 多个安装候选 | 让用户选择实际运行的桌面端 |
| 锚点不唯一/不存在 | 停止；记录目标版本和上下文，不做模糊替换 |
| 修改分支无可靠 ASAR writer / 零改动 round-trip 失败 | 停止；不得临时下载或盲写归档 |
| integrity 无法逐条复验 | 停止；“可以解包”不能替代完整性证明 |
| Electron embedded-ASAR/fuse/签名策略不明或拒绝修改 | 停止；不绕过安全策略 |
| 标签仅为“重启/Restart” | 判定部分安装；按权威提示词修正完整产品名 |
| 备份哈希不一致或目录已存在 | 停止；创建全新不覆盖的可靠备份 |
| 源码任一变化落在两个允许语义区域之外，或修改了本不需要修正的区域 | 丢弃 staged 产物，保持正式文件不变 |
| 非目标内容或语义元数据出现差异 | 丢弃 staged 产物，保持正式文件不变 |
| 正式文件或备份中途变化 | 停止；重新从基线开始 |
| 重启后没有菜单 | 恢复/重装当前版本，重新探测，不叠加补丁 |
| 点击后不重新拉起 | 检查回调上下文与退出顺序；不要引入第二托盘兜底 |
